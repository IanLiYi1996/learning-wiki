# 四个离线练习：预算、时延、过期结果与说话时机

整理日期：2026-11-09。[专题导读](README.md)。全部是本 Wiki 的原创教学算例，不是 Higgs 模型、MOPD trainer 或官方 benchmark 的实现。

只用 Python 3.9+ 标准库，不采集音视频、不调用网络、GPU、模型或付费 API，也不写入外部系统。源码：[realtime_interaction_lab.py](https://github.com/IanLiYi1996/learning-wiki/blob/main/scripts/realtime_interaction_lab.py)；测试：[test_realtime_interaction.py](https://github.com/IanLiYi1996/learning-wiki/blob/main/tests/test_realtime_interaction.py)。新文件尚未发布时，网页源码链接需等仓库发布后才能使用。

在仓库根目录运行：

```bash
python -B scripts/realtime_interaction_lab.py
python -B -m unittest discover -s tests -p 'test_realtime_interaction.py' -v
```

输出为 JSON。没有训练循环、模型权重、真实工具或生产性能测量。

## A. 名义表示预算，不是账单

`stream_budget(160, 2, 3, 5, 10, 2, 4)` 与 [02 的原创配置](02-streaming-codecs-and-rendering.md)一致：

| 结果 | 值 |
| --- | --- |
| 每分钟块数 | 375 |
| 输入音频／输出音频 | 750／1125 |
| 输入视觉／输出脸部 | 750／750 |
| 合计单位／分钟 | **3375** |
| 最近四分钟的单位数 | **13,500** |

这是稳态平均速率，不含开始时的采样相位、文字、工具和摘要；它不是完整上下文大小，也不是实际计算量。即使变量写 audio／face，也只是数字，没有处理真实音频或图片。

视频关闭时可以将 `video_units` 设为零，画面输出关闭时也可把对应速率设为零，但这不模拟生产系统实际省下多少费用。负数、布尔值、非有限值、非法采样周期及浮点溢出会被拒绝。

## B. 流分块不能替代端到端时延

七个**声明为串行**的假想阶段 80、25、15、45、20、25、40 ms，`serial_latency` 返回 **250 ms**。

`block_alignment(160)` 返回平均对齐等待 **80 ms**、等待上确界 **160 ms**。条件是事件均匀到达且必须等整块结束；这个函数不包括模型计算或播放。真正流水线的重叠需要用事件依赖和时间戳寻找关键路径，不能直接调用这个求和器当生产延迟测量器。

练习：如果“我正在查”在 200 ms 时响起，最终可靠库存结果 2 秒后才到，首次声音和有用答案是否相同？**不相同，二者起止点要分别记录。**

## C. 新需求不能使用旧工具结果

`ToolResult` 表示不可变的小记录，`result_gate` 演示一个**只读回答准入**检查：任务 ID、意图版本、观察时间的新鲜度，以及是否 final。

示例当前需求是 `inventory/v2`，当前时间 2 秒，最大年龄 1 秒：

| 结果 | 检查结果 |
| --- | --- |
| v1 的最终结果 | `old-intent` |
| v2 的中间结果 | `not-final` |
| v2 的新鲜最终结果 | `admit` |
| 别的任务结果 | `wrong-task` |
| v2 但超过年龄限制 | `expired` |

`observed_at` 指观察对应的时刻，不只是收到消息的时刻。未来观察会报错；恰好达到年龄限制的结果仍允许进入。这是明确的教学约定，不是普遍业务规则。

通过准入不等于验证事实正确，更不等于有权执行写入；失败也不会删除记录、撤销订单或停止实际工具。真正系统还需要权限、签名、结果版本、工具 schema 和审计。

练习：用户打断朗读，却没有改库存型号，是否所有查询都应过期？**不是，输出中断与意图变更要分开。**

## D. 提醒过多也算错

期望时间窗为 `[1,2]`、`[5,6]`、`[9,10]` 秒；预测发声时刻为 1.5、1.6、5.5、12 秒。

`timing_score` 采用一对一命中，得到 **TP=2、FP=2、FN=1**，precision **0.5**，recall **2/3**，F1 **4/7**。同一窗里第二次发声不再次计分；窗外发声是额外提醒。

窗口是闭区间，互相接触或重叠会拒绝，避免边界匹配歧义。空预测得零覆盖，空期望窗口不用于本练习；真实任务中应另外设计“全程应沉默”的评价。预测顺序不影响本例的分数。

这个 toy 没有内容正确性、容忍阈值、语音持续时间、轮次权重或 PAUC；不是 Full-Duplex-Bench／ProactiveVideoQA 的替代实现。见[05 的测量合同](05-evaluation-and-safety.md)。

## 自测与参考答案

1. 四分钟 13,500 单位证明上下文总长固定了吗？**没有，还遗漏文字、工具和旧历史等。**
2. 时延求和 250 ms 可以说成 Higgs 实测吗？**不能，这是原创串行假设。**
3. 工具结果 final 且新鲜，能否直接付款？**不能，回答准入不提供执行权限。**
4. 重复“我看到了”越多，时机分就越高吗？**不会，一对一命中会惩罚额外发声。**
5. 一次 F1 改善证明事实准确率改善了吗？**没有，本例没检查说出的内容。**

本地验证能确认数字、输入检查和文档保持一致，不能证明模型理解、服务质量或安全。下一步应先写合成任务和验收合同；真实用户素材、账户写入与付费实验需另行授权。
