# 04 训练交互策略：不仅教说什么，也教何时行动

核查日期：2026-11-09。[专题导读](README.md) · [来源与边界](sources.md)。

## 1. 文字能力与视听接口不是同一件事

Boson 描述从文本预训练起点继续做多模态训练，再进行交互后训练。持续的文本训练旨在保留语言能力，但这是一种训练目标，不是能力完全不损失的证明。[Boson 训练说明][boson]

用原创问题分解一条学习路线：

1. 模型能否解释文字指令？
2. 音频／视频表示是否携带足够的信息？
3. 模型能否把当前流与历史任务关联？
4. 它能否在合适时间说、停、等、查或委派？
5. 新能力是否损害了原有任务与安全边界？

“新增音频入口”只解决第二步的一部分；“做了 RL”也不保证后面三步成功。已有[语音适配专题](../openmoss/01-audio-representation-and-generation.md)讨论共享骨干与能力保留的冲突。

## 2. 一条交互轨迹包含哪些监督？

原创例：用户正在读一个长序列号，助手中间说“收到”，误把前半段当完整编号并开始查询。最终答错，原因可能不是编号知识不足，而是过早行动。

因此教学上应分开：

- 内容监督：回答、转写或任务参数是否正确。
- 时机监督：等待、发声、让步的时刻是否合适。
- 状态监督：使用的是不是当前意图和正确工具结果。
- 结果监督：任务完成、约束满足、成本和风险是否合格。

Boson 公开列出的 specialist teachers 面向自然会话、交互行为、动态委派和任务完成；但没有给出每个目标的完整数据、奖励和 loss。[Boson 后训练说明][boson]

## 3. GRPO 负责改策略，OPD 负责什么？

GRPO 是策略优化方法；教师蒸馏是向学生传递行为或分布的一类方法。DeepSeekMath 的 GRPO 用同题组内相对奖励构造学习信号，不把“有 teacher”当成 GRPO 的定义。[DeepSeekMath][grpo]

原创直觉：为同一交互条件采多个候选轨迹，比较是否正确完成、有没有抢话、是否越权，再鼓励较好的候选。组内相对分数只说明“比这组其他候选好”，不意味着绝对正确；若奖励只看结局，还可能漏掉中途糟糕的交互。

**On-policy distillation／同策略蒸馏**强调学生沿自己产生的轨迹学习教师反馈，减少只模仿专家轨迹时的分布错位。这里的“on-policy”取决于实际采样策略及其刷新，不取决于方法名称。[GKD 原论文][gkd] · [本站 OPD 源码读本](../training/agentic-rl-lab/on-policy-distillation.md)

## 4. 多教师合并的一个教学模型

设学生为 $S_\theta$，教师为 $T_j$，学生访问到的状态为 $h$。如果各教师与学生共享输出空间，一个可能的**教学目标**是：

$$
\mathcal L_{\rm teach}=
\mathbb E_{h\sim d_{S_\theta}}
\sum_j\lambda_j(h)
D_{\rm KL}\bigl(S_\theta(\cdot\mid h)\Vert T_j(\cdot\mid h)\bigr).
$$

这里 $\lambda_j(h)\geq0$ 且总和为 1。公式只帮助思考“哪些状态由哪些教师提供信号”，不是 Boson MOPD 的已公布公式，也没有给出完整轨迹分布梯度。

还可以选择教师混合分布后再做 KL，或者按任务路由教师；这些目标通常不等价，不能在不知道实现时互换。如果教师和学生的音频码、词表或动作接口不同，上述分布也不能直接比较，需要另行设计对齐或行为监督。

关键问题是：

| 检查项 | 为什么重要 |
| --- | --- |
| 谁产生状态／轨迹？ | 教师轨迹与学生部署时的错误前缀不同 |
| 教师是否冻结、何时刷新？ | 训练目标可能随时间变化 |
| 教师如何混合？ | 礼貌、抢答、成本、任务成功可能冲突 |
| 哪些位置接受 loss？ | 用户声音与工具观察不是模型采样的动作 |
| 反馈是 token 概率还是整段行为分？ | 两者信号密度与偏差不同 |
| 学生和教师使用哪些额外信息？ | 训练期特权不能偷偷进入最终测试 |

这些是原创审计建议。可与 [Agentic-RL Lab 的真实 OPD／OPSD 实现](../training/agentic-rl-lab/on-policy-distillation.md)对照，但不要据此补全 Boson 未公开的训练细节。

一个可具体阅读的公开 MOPD 实例，从共同 SFT 起点训练领域 RL 教师，学生自己 rollout，再按任务路由给对应冻结教师，接受 reverse KL 监督。它不是每个 token 都平均所有教师，也不是模型权重合并；同名论文与 Boson 文章之间，没有足够证据确认配方一致。[公开 MOPD §3][mopd] · [来源与不等同边界](sources.md#mopd)

## 5. “自我改进”应检查哪一层？

Boson 称其闭环为 RSI：系统在模拟环境交互，分析失败，生成针对性数据，训练后再次迭代。[Boson 训练说明][boson]

把这个陈述拆成可检验的问题：

1. 更新后的模型在新的持出交互上是否改善？
2. 改善是否来自更好的数据，而不是更多预算或熟悉模拟器？
3. 生成数据／设计实验的“改进器”自身是否变强？
4. 这种改进能否跨多个周期、任务和环境持续？

原文提供了闭环设计描述，却没有独立证明第 3、4 项。循环训练不自动等于改进能力递归增强。理论与证据判准见[自我改进基础](../self-improvement/concepts-and-foundations.md)。

## 6. 模拟器可以教行为，也会制造捷径

原创风险：如果模拟用户每次喊“停”都恰好静音 1 秒，模型可能学习静音长度，而不是理解真实打断。若奖励器总偏好立即接话，又可能把沉默判断训练坏。

建议保留不同语言、口音、多人、噪声、犹豫、重叠与任务改口的独立测试；训练用 judge、开发选点和最终验收分离。改变模拟器、奖励、学生或预算时分别做消融，才能归因。
