# 04｜稳定币、多链与跨链：按信任机制整理

- 对应 PPT：28–42、48–51
- 核验日：2026-10-29
- 目标：识别资产支持、执行、安全、数据和互操作各自负责什么
- 更细证据见 [生态核验记录](../notes/ecosystem-source-audit.md) 及 [二次复核](../notes/follow-up-verification.md)

## 1. 稳定币先回答三个问题

1. **链上表示在哪里？** 网络、合约 / mint / 原生 denom。
2. **价值支持来自哪里？** 银行储备、链上抵押、链下头寸还是内生兑换机制。
3. **谁能兑现与控制？** 赎回资格、冻结、铸销、升级、预言机和清算。

这是本次分析框架。目标价格、储备净值、单币赎回价值、二级市场价格不是同一个量。

PPT “稳定币不是链”有助于区分 USD₮ 与 Ethereum，但“都是合约，余额都在 storage mapping”只适用于某类实现。Solana 的 SPL 资产通过 Token Program / Mint / Token Account 表示；历史 Terra UST 则属于链的原生资产体系。[S03][C20]

## 2. 四种机制是教学分类，不是互斥的永久标签

| 机制 | 典型支持方式 | 核心依赖 | 压力测试问题 |
| --- | --- | --- | --- |
| 法币储备型 | 链下现金、短债等储备与铸销 | 发行方、银行 / 托管、兑付路径 | 储备可否及时变现，谁可以直接赎回 |
| 抵押借贷型 | 资产抵押后产生债务 | 抵押质量、预言机、清算、治理 | 波动、拥堵、清算流动性和坏账怎样处理 |
| 合成 / 对冲型 | 支持资产与衍生品等组合 | 交易、托管、保证金、资金成本 | 对冲偏差、负资金费率、赎回流动性 |
| 内生算法型 | 以相关代币铸销与套利调供需 | 相关代币价值、市场深度、信心 | 兑付压力是否反过来破坏支持资产 |

上述机制来自发行方与协议资料的归纳，不代表任何类型零风险。实际产品可混合机制，配置也可变化。[C01][C03][C05][C07][C09][C20]

本专题不沿用 PPT 的市场规模、份额、排名或治理代币价格。

## 3. USDT / USDC：链上铸销与链外兑现

发行方在多网络部署或维护认可的资产表示，不代表网络间可以直接普通转账。钱包必须按发行方当前名单核验资产，不凭 `USDT` / `USDC` symbol。[C01][C04]

2026-10-29 查阅 Tether 名单：

- Ethereum、Tron、Solana 等有对应 USD₮ 标识。
- BNB Smart Chain 小节列的是 XAU₮，不是 USD₮；Polygon 未列为官方 USD₮ 网络。不能据此认定任意 BSC / Polygon 同名资产都是原生 USD₮，具体包装来源仍需查合约。
- Omni、BCH SLP、Kusama、EOS、Algorand 的旧版本不再被直接发行或承担相同赎回支持；2025-08-29 更新撤回了冻结旧链合约的计划。停止支持不等于所有持有人间转账都被禁。[C01][C02]

Circle 披露月度储备鉴证，也另行披露公司财务审计，两者范围不同。网站展示的 1:1 兑付描述还需与条款中的适用范围、账户资格和支持资产定义对读。本次仅解释产品机制，不为具体持有人判定法律资格。[C03][C04]

工程建议：资产目录保存发行方认可状态、原生 / 包装标记、合约、精度、赎回对象和管理员能力；分别显示发行方风险和底层链风险。

## 4. DAI / USDS：从超额抵押入门，但不能停在 ETH 示例

ETH 抵押 → 形成债务 → 还款 → 释放抵押品，是解释 Vault 的入门模型，不是当前全部系统资产清单。[C05][C06]

已核验的具体路径：

- Sky LitePSM 核心交换 USDC / DAI。
- UsdsPsmWrapper 暴露面向 USDS 的 USDC 交换接口。
- Maker / Sky 的 RWA toolkit 提供链外资产借贷、放款 / 回款及清算执行相关模块。[C05][C06]

因此不能写“完全无机构”“资产完全链上可验证”“纯 ETH 支撑”。链上余额可以查，银行、发行方、抵押资产执行和权限仍存在链外依赖。

本次未完成同期抵押库存、比例和治理参数核验，不填精确配置。也不把 DAI、USDS、sUSDS 或其治理代币当作同一资产。

工程练习：画出抵押品、稳定币、oracle、liquidation、PSM 和链外执行者的关系；标出哪些状态能链上查证，哪些还需机构证据。

## 5. USDe：对冲目标不等于永恒等值

PPT 的“现货 + 等额做空”解释了一种核心风险对冲，但 2026-10-29 的官方资料已描述更广泛资产 / 策略类别。对波动资产匹配空头是其中一条路径，稳定资产则不需要相同对冲。哪些类别已实际持有、比例多少，本次没有核验，应与动态配置分开。[C07][C09]

基本拆法：

```text
支持资产
  + 相关衍生品损益 / 资金成本
  + 托管与保证金安排
  + 赎回与二级市场流动性
  → 相对稳定的目标，而非无条件保证
```

Off Exchange Settlement / 托管安排可以减少某些交易所暴露，却不消除托管、对手方、流动性和执行风险。负资金费率会增加成本；reserve fund 和动态配置是缓冲设计，不是无限担保。[C07][C08]

USDe 与 sUSDe 分开：后者是质押后持有的奖励承载表示。正收益示例不用于推导未来收益或绝不脱锚。[C07]

## 6. UST：把失败机制与数字损失分开

Terra Classic 历史资料描述 UST / LUNA 的协议铸销与套利；迁移说明明确，旧 market swap 的 mint / burn 路径已禁用。这里把它作为历史设计讨论，不当成当前可操作兑付通道。[C20][C21]

教学推论：

```text
稳定币抛售压力
  → 兑为相关代币
  → 相关代币供应增加 / 卖压增加
  → 其价格和支持能力降低
  → 进一步损伤兑付信心
```

当支撑资产价值与信心相互依赖，稳定机制可能在压力下转为正反馈。PPT 中具体损失金额和日内跌幅未做单独复盘，不搬进正文作为已验证数据；不将这一案例外推成“任何算法设计必然完全相同”。

## 7. L1、sidechain、rollup 与 validium

先问执行、排序、数据和验证分别在哪里：

| 类型 | 主要安全 / 可验证性边界 |
| --- | --- |
| 独立 L1 | 自己的共识及状态验证 |
| Sidechain | 独立共识；连接 Ethereum 不自动继承全部安全 |
| Optimistic rollup | L1 承诺与数据、争议 / fault proof；还要审查挑战机制和退出 |
| ZK rollup | 有效性证明及 L1 数据可用性；仍有实现、升级和可用性风险 |
| Validium | 有效性证明，但数据不按 rollup 相同方式放在 L1，另有可用性边界 |

零知识 / 有效性证明主要证明执行关系；它不会凭空让所需数据持续可获取，也不会自动消除管理员、排序器或桥的风险。[C10][C18][C19]

Polygon 要按具体产品说：

- Polygon PoS 是侧链，不能因品牌被统称为 Rollup L2。
- Polygon zkEVM Mainnet Beta 是历史 rollup 产品。官方现状页称其 sequencer 已于 **2026-07-03** 退役，停止出块，常规桥提款不再处理；特定 EOA 资产有独立 Claims 路径，不能外推至合约中全部资产。
- 该退役不代表 Polygon PoS、CDK 或 Agglayer 全部停运。当前方案选择必须重新查对应产品，而不是沿用 PPT 的“zkEVM 是当前战略核心”。[C10][C11]

本次没有连接 Claims 或测试退出功能。

## 8. Polkadot / Cosmos：框架、安全与消息分开

PPT 的“共享安全 vs 主权独立”有教学价值，但不是两个生态所有配置的充分描述。

Polkadot 的长期插槽拍卖是历史机制；官方 Wiki 说明 2024-09-19 启用 Agile Coretime，按 bulk / on-demand 资源分配解释现行安排。“替代长期拍卖”也不等于没有任何定价或竞价机制。[C12]

XCM 是 Cross-Consensus Message Format，不负责定义消息怎样实际送达；XCMP / HRMP / VMP 等渠道要另讲。消息格式、传输、安全和资产执行是四项不同职责。[C13]

Cosmos SDK 是应用专用链的模块化框架，不是 Cosmos Hub 的子链 SDK；IBC 是互操作协议，不限 Cosmos SDK / “Cosmos 域”。采用 IBC 不自动获得共享安全；共享安全需要另外选择及部署。[C14][C15]

共享安全的一般机制不代表 Cosmos Hub 目前仍提供旧 ICS 服务。追加核验的官方 Hub 文档与 Gaia v28.0.0 发布说明明确，provider 模块已经移除；旧 consumer 启动教程不能作当前 Hub 接入步骤。详见 [多链升级篇的现状与机制分层](../upgrades/03-multichain.md)。[当前Hub说明](https://docs.cosmos.network/hub/latest/getting-started/what-is-gaia)、[v28发布说明](https://github.com/cosmos/gaia/releases/tag/v28.0.0)

因此：

- 不将 DOT / ATOM 市价当作通信或共识安全证据；
- 不说“IBC / XCM 绝不能连接 Ethereum”；
- 也不因文档列出一个生态，就说其所有链、资产、方向和版本都已互通。

## 9. Solana：执行结构与共识升级分开读

程序逻辑与状态账户分开，交易显式声明账户访问，提供对无冲突访问安排并行执行的基础。PDA 是 program ID / seeds 等确定性派生、无对应私钥的地址；地址派生不代表已经有账户或资产。[S05]

Token Program 定义指令，Mint 标识资产，Token Account 记持有人某种 mint 的余额，ATA 是常用可推导 Token Account。不能把 SPL USDT 解释成每个用户拥有独立 ERC-20 mapping，或把 mint 当成 Token Program。[S03]

**截至研究日的官方状态声明**：Solana Foundation 升级页称 Alpenglow 于 **2026-10-21** 主网 epoch 1064 启用，Votor 替代原 TowerBFT 投票层，Rotor 仍是未排期的后续阶段。页面同时指出原 PoH 出块节奏机制、投票交易统计与部分索引语义已改变；SVM 执行未随之替换。[C16]

这意味着 PPT 的“PoS + PoH、0.4 秒、把投票算进的数千 TPS”不能直接作为当前钱包设计输入。官方的目标 finality 也不是本次实测吞吐或固定 SLA。主线程复核了英文升级页，未自行验证 feature gate 或重放主网数据。

Solana 官方有 2024-02-06 中断复盘；这个历史事件可以讨论具体原因，不能用它推出当前故障率，更不能据“未找到 Ethereum 事故”写“从未宕机”。[S06]

## 10. 桥：消息验证和资产兑现是不同风险

PPT 的 lock-and-mint 是常见模式之一，不是所有跨链都如此。Ethereum 桥文档还列出 burn-and-mint、原子交换等模式。[C22]

推荐按五层审查：

1. 源链事件是否最终 / 会否重组。
2. 目标侧如何验证事件：托管、委员会、轻客户端、proof 等。
3. 合约与 relayer 的执行、重放保护和消息格式。
4. 资产流动性、储备、映射关系及直接赎回资格。
5. 升级、暂停、恢复与应急权限。

这是一套评审框架。轻客户端或 ZK 可改变信任假设，但不自动清除其余四层风险。“所有桥都不安全”太粗；“某桥用了 ZK 所以安全”同样太粗。

包装 BTC、发行方多链稳定币、流动性桥转移和跨链消息应分别建资产记录。PPT 的桥事故损失金额只留在原文，未逐案例一手复盘，不作为本次统计。

- 为什么 Circle 的月度储备鉴证不能证明整个系统不可能出故障？
