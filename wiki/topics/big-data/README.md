# 大数据技术

大数据技术不要按产品名称整理，而要围绕“数据从产生到产生价值”的过程建立知识体系。
工具会变化，问题、概念和架构权衡相对稳定。

## 一条主线

```text
数据源
  -> 采集与传输
  -> 存储与数据建模
  -> 批处理 / 流处理
  -> 查询与数据服务
  -> 业务语义与操作层
  -> 分析、应用与机器学习
```

以下能力横跨整条链路：

```text
调度编排 | 元数据与治理 | 数据质量 | 安全权限 | 可观测性 | 成本与资源管理
```

遇到任何新技术时，先判断它在这条链路中的位置、解决的问题以及与上下游的边界，
再记录它的 API、配置和操作方法。

## 技术分层

| 层次 | 核心问题 | 应重点掌握的概念 | 代表性技术类型 |
| --- | --- | --- | --- |
| 基础理论 | 单机无法完成时，系统如何扩展并保持正确 | 分布式系统、分区、复制、一致性、容错、并行计算、网络与磁盘 | 操作系统、网络、分布式算法 |
| 数据源 | 数据从哪里产生，以什么形态变化 | 业务数据库、日志、事件、文件、API、IoT、数据契约 | OLTP、日志系统、事件系统 |
| 采集与传输 | 如何可靠、及时地移动数据 | 批量同步、CDC、消息队列、事件顺序、重复投递、背压 | 数据集成、消息与事件流平台 |
| 存储与建模 | 如何低成本保存并高效组织数据 | 文件格式、压缩、分区、索引、数据模型、对象存储、分布式文件系统 | 数据湖、数仓、NoSQL、对象存储 |
| 计算处理 | 如何对海量、有界或无界数据执行计算 | 批处理、流处理、状态、事件时间、窗口、水位线、检查点 | 分布式计算引擎 |
| 查询与服务 | 如何让数据被交互式查询或在线应用消费 | SQL、OLAP、MPP、向量化执行、缓存、搜索、低延迟服务 | 查询引擎、OLAP、搜索、KV 服务 |
| 业务语义与操作 | 如何把数据、逻辑和业务动作组织成可复用能力 | 业务对象、关系、本体、语义层、Actions、Functions、决策血缘 | 企业本体、知识图谱、操作语义层 |
| 湖仓与表管理 | 如何在开放存储上获得可靠的表语义 | ACID、快照、Schema 演进、时间旅行、Compaction、Catalog | 开放表格式、湖仓平台 |
| 调度与编排 | 如何稳定运行相互依赖的数据任务 | DAG、依赖、重试、补数、幂等、回填、SLA | 工作流编排平台 |
| 治理与质量 | 如何知道数据是什么、是否可信、由谁负责 | 元数据、血缘、数据目录、质量规则、主数据、数据契约 | Catalog、质量与治理平台 |
| 平台与运维 | 如何以合理成本长期运行系统 | 资源隔离、弹性、监控、日志、追踪、容量、FinOps、灾备 | 容器、资源调度、可观测平台 |
| 安全与合规 | 谁可以在什么条件下访问哪些数据 | 身份认证、授权、加密、脱敏、审计、保留策略 | IAM、密钥与审计系统 |

## 四种笔记

### 1. 概念笔记

解释稳定的原理，例如分区、Exactly-once、事件时间、列式存储。

至少回答：

- 它解决什么问题？
- 为什么简单方案不够？
- 核心机制是什么？
- 有哪些边界和代价？
- 它与哪些概念容易混淆？

### 2. 技术笔记

记录具体系统，但围绕能力和权衡，不照抄安装文档。

使用[技术笔记模板](technology-note-template.md)，重点回答：

- 它位于数据链路的哪一层？
- 核心抽象和执行模型是什么？
- 一致性、延迟、吞吐和成本如何权衡？
- 它替代什么，又不能替代什么？
- 什么情况下不应该使用？

### 3. 架构笔记

用一个业务场景串联多个组件，记录数据流、控制流和故障处理。

至少包含：

- 需求与约束
- 数据规模和时效目标
- 架构图与数据流
- 技术选型及备选方案
- 数据正确性与失败恢复
- 安全、监控和成本

### 4. 实验与复盘

通过可复现实验验证理解，例如吞吐测试、故障注入、数据倾斜和状态恢复。

至少记录：

- 假设
- 环境与数据集
- 步骤和命令
- 指标与结果
- 结论及其适用范围

## 整理每项技术的固定顺序

```text
业务问题
  -> 核心概念
  -> 系统模型
  -> 数据正确性
  -> 性能与成本
  -> 运维与故障
  -> 适用场景
  -> 实践验证
```

这个顺序能避免笔记退化为参数手册。

## 技术选型的统一维度

比较技术时使用同一组问题：

| 维度 | 需要回答的问题 |
| --- | --- |
| 数据特征 | 有界还是无界？结构化程度如何？更新频率多高？ |
| 数据规模 | 日增量、存量、峰值吞吐和未来增长是多少？ |
| 时效 | 允许小时、分钟、秒还是毫秒级延迟？ |
| 正确性 | 是否允许重复、丢失、乱序或短暂不一致？ |
| 查询模式 | 点查、扫描、聚合、搜索还是混合负载？ |
| 可靠性 | 如何重试、恢复、回放、补数和灾备？ |
| 可扩展性 | 扩容是否线性，是否存在协调节点或热点？ |
| 运维复杂度 | 部署、升级、监控和故障定位成本如何？ |
| 生态兼容 | 数据格式、协议、Catalog 和上下游是否开放？ |
| 总成本 | 计算、存储、网络、人力和迁移成本分别是多少？ |

## 推荐学习路线

详见[大数据学习路线](learning-roadmap.md)。

总原则是先掌握稳定概念，再学习一套端到端系统，最后扩展技术广度：

1. 计算机与分布式基础。
2. SQL、数据建模、文件格式和存储。
3. 完成一条离线数据链路。
4. 完成一条实时数据链路。
5. 学习湖仓、治理、质量和平台化。
6. 用真实项目验证性能、正确性和运维能力。
