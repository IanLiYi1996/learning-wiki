# 支付术语速查：先懂意思，再记缩写

这些是便于学习的释义，不是全球统一的法律定义。具体边界与出处见[完整读本](payment-industry-101.md)和[来源](sources.md)。

## 角色与产品

| 名词 | 白话解释 | 最容易混淆 |
| --- | --- | --- |
| Issuer／发卡方 | 提供卡产品、管理卡账户与授权责任的主体 | 不等于只提供发卡 API |
| Acquirer／收单方 | 商户侧收单关系与责任主体 | 不等于 Gateway |
| Card Network／卡网络 | 连接发卡与收单并提供规则及网络能力 | 不等于持卡人的贷款银行 |
| Processor／处理方 | 处理交易报文，可在发卡或收单侧 | 不必独立持有资金 |
| Gateway／网关 | 安全连接商户与支付处理能力 | 不因 API 接通就承担全部结算责任 |
| PSP | Payment Service Provider，支付服务整合方 | 不等于全球自营收单 |
| PayFac | Payment Facilitator，按网络安排管理子商户 | 不等于所有 SaaS／市场平台 |
| Sub-merchant | 被某种平台／PayFac 模式管理的子商户 | 不等于没有商户核验 |
| MoR | Merchant of Record，面向买家的交易责任主体 | 不仅是资金路由参数 |
| Orchestration | 多个支付能力的统一路由与运营管理 | 不会自动使 Token 跨服务商通用 |
| Program Manager | 管理发卡产品、运营与伙伴关系的角色 | 不自动等于持牌发卡机构 |
| BIN Sponsor | 为卡项目承担相应发卡／网络责任的合作机构 | 名称不替代合同和具体法律主体 |
| Virtual Card | 没有实体卡片的卡凭证／卡产品 | 不是支付牌照，也不一定是 EMV Token |
| Wallet | 管理余额、凭证或两者的用户入口 | 不能仅凭界面判断资金模型 |
| Embedded Payments | 把支付嵌入经营软件或流程 | 是交付方式，不是独立 Rail |

## 交易与资金

| 名词 | 白话解释 | 最容易混淆 |
| --- | --- | --- |
| Authentication | 验证操作主体或身份 | 不等于授权获批 |
| Authorization | 对支付请求作批准／拒绝判断 | 不等于最终到账 |
| Capture | 商户正式请款 | 不总是紧随授权自动完成 |
| Clearing | 交换处理金融交易信息并确定义务 | 不只是移动资金 |
| Settlement | 依安排完成资金义务 | 不一定是商户外部银行到账 |
| Payout | 从体系内余额向外部收款账户出款 | 发起不等于已收到 |
| Reconciliation | 匹配支付、业务与金融记录 | 总额相等不保证每笔正确 |
| Refund | 发起退还已付款项 | 不是删除旧账 |
| Reversal | 一种撤销／冲回表现，含义看环节 | 账单字样不能独自判定是取消还是退款 |
| Dispute | 对交易提出正式争议 | 不一定都已发生拒付扣款 |
| Chargeback | 按卡争议机制扣回相关款项 | 不只因盗卡发生 |
| Reserve | 按安排保留、暂不可支付出的资金 | 不等于自由现金或额外收入 |
| Ledger | 记录权益、余额和金融事件的账本 | 不等于某个实时显示数字 |
| Double-entry | 每个记账事件保持借贷平衡 | 平衡仍不保证业务金额正确 |
| Liquidity | 适时、适币种、适账户的可用资金能力 | 有资产不等于眼下能付款 |
| Prefunding | 预先放置支付所需资金 | 不等于 FX 或 PvP |
| Finality | 规则与法律定义的最终转移／义务解除 | 不等于 UI 显示成功 |

## 账户、跨境与企业流程

| 名词 | 白话解释 | 最容易混淆 |
| --- | --- | --- |
| Rail | 完成支付的网络／机制，学习用统称 | 不把所有入口叫 Rail |
| A2A | Account-to-Account，账户之间支付 | 不必实时 |
| ACH | 自动清算所类账户支付安排 | 同日不等于逐笔即时 |
| RTGS | Real-Time Gross Settlement，实时逐笔全额结算 | 不自动 24×7 |
| DNS | Deferred Net Settlement，延期净额结算 | 客户可以更早获得资金可用性 |
| RTP® | 本读本特指美国 TCH 的实时支付网络 | 与 generic real-time payments 区分 |
| FedNow | 美联储即时支付基础设施 | 不是消费者钱包／数字货币 |
| Pix | 巴西即时支付方案 | 区分方案、SPI 和同机构交易 |
| UPI | 印度 NPCI 运营的支付系统 | 别称为印度 RTGS |
| PayNow | 新加坡别名寻址与支付服务 | 不等于独立的 RTGS |
| SEPA | 欧元支付的协调范围与规则框架 | 不单指一个清算机构 |
| SCT／SDD／SCT Inst | SEPA 信用转账／直接借记／即时信用转账 | 规则与处理设施分开 |
| PISP／AISP | 发起账户支付／提供账户信息的服务角色 | 数据接入不等于资金保管 |
| SWIFT | 金融报文网络 | 不替银行持有客户转账资金 |
| CIPS | 跨境批发支付清算基础设施 | 不简单等同报文网络 |
| FX | 货币转换与相关交易 | 不只是改报文币种字段 |
| Nostro／Vostro | 往来账户从两家银行视角的称呼 | 不是一种特殊货币 |
| PvP | 两种货币的最终交割相互关联 | 不等于两条消息同时送达 |
| AP／AR | 企业应付／应收管理 | 不是独立结算网络 |
| Bill Pay | 账单支付流程 | 可选择多种付款方式 |
| B2B／P2P | 企业对企业／个人对个人的场景 | 不决定用哪条 Rail |

## 安全、凭证与指标

| 名词 | 白话解释 | 最容易混淆 |
| --- | --- | --- |
| PAN | Primary Account Number，支付卡主账号 | 不是所有 Token |
| Tokenization | 将敏感凭证换成受相应机制管理的替代值 | 不等于任意加密字符串 |
| 3DS | 卡不在场场景的持卡人认证机制 | 不等于发卡支付授权 |
| PCI DSS | 支付卡账户数据安全要求 | 不等于支付经营牌照 |
| KYC／KYB | 认识个人／企业客户及相关身份关系 | 不只是开户一次验证 |
| AML | 反洗钱控制体系 | 不等于一般欺诈模型 |
| Sanctions | 制裁与禁止对象／交易的限制 | 身份真实不等于可交易 |
| Safeguarding | 特定制度下的客户资金保护安排 | 不等于存款保险 |
| Idempotency | 同一意图重试不产生重复效果的设计 | 外部 API 幂等不覆盖全部副作用 |
| Webhook | 服务方异步通知事件的接口机制 | 不默认唯一且顺序到达 |
| MDR | Merchant Discount Rate，商户折扣费率 | 不等于 PSP 保留的净收入率 |
| Interchange | 常见卡购买中收单侧向发卡侧支付的交换费 | 不等于卡组织收入 |
| TPV | Total Payment Volume，支付总额指标 | 定义和范围由披露方决定 |
| Take Rate | 同口径收入相对支付量的比率 | 不先定义口径就不能比较 |
| bps | 基点，1 bps = 0.01 个百分点 | 100 bps = 1 个百分点 |
| Authorization Rate | 特定分母下授权获批比例 | 重试与排除项会改变结果 |
| Fraud Loss | 定义范围内最终承担的欺诈损失 | 不等于所有被拒交易 |
| Cost per Transaction | 选定成本相对选定笔数 | 不是只看机器费用 |
| BNPL | 先买后付的信用／还款产品安排 | 不只是钱包按钮 |
| Stablecoin | 稳定价值目标的数字资产安排 | 目标不等于无风险保证 |
| Agent Mandate | 用户给予代理的受约束委托 | 不等于发卡方支付授权 |

不必背完。遇到新公司时，优先圈出：**谁、账户、网络、责任、收入、风险、证据**。
