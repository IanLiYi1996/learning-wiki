# Physical AI：业界产品与端到端方案

2026-10-27｜行业篇 1.0。补充已有原理教材，回答各阶段有哪些现成产品、怎样交付和连接，以及公开证据能说明什么。

最终 PDF 为 42 页，约 2.8 万汉字，58 条产品／工具／应用方案记录，147 个一手来源 URL 入口。记录中分别标注获取、交付、客户案例、试点、预览和维护状态，不把这 58 条统一称作已完成生产验收的产品。

## 结构

第 1 章定义阶段与证据口径；第 2—10 章逐阶段介绍数据、仿真、合成、训练、模型、感知／控制、部署、验证和现场运行；第 11 章给产品组合与客户案例，第 12 章把接口和原理教材对上。

每张主要卡片包括职责、输入输出、获取／部署、衔接、公开状态及边界。商业软件、开源组件、可下载权重、受限 API 和完整机器人应用分别介绍，不合成排行榜，不根据宣传演示推断客户量产。

研究采用 research 的一手来源要求；humanizer-zh 用来删除宣传词、把职责与接口写清楚。officecli 用于 Word 的排版、结构与引用检查。客户官网、供应商案例和软件文档分别保留证据范围。

## 案例的使用方式

参考组合是本册的工程拆解，不冒称客户原始架构或厂商一体化支持包。真实案例保留时间、任务与披露方；未来扩展和已有运行分开。

行业篇没有进行安装、模型运行、机器人试验或客户系统接入。数据存储、许可、订阅、供货和支持条件可能更新；价格、区域与合同条款未逐项核验。

## 构建

需要 Python、uv、Pandoc、officecli 和 Noto Sans CJK SC 字体。

```bash
python build.py --format assemble
uv run --with markdown --with weasyprint --with pymupdf python build.py --format pdf
python build.py --format docx
```

`chapters/` 是分章正文，`notes/*products.json` 是产品记录。合稿把章节研究用来源清单收拢到附录 C，按首次出现生成 S 编号；重复产品按名称与供应商合并阶段和来源。CSV 用 UTF-8 BOM，复合字段保留为 JSON 字符串。

`qa/` 保存结构、引用对应、产品记录与视觉检查。Word 的目录及页码是动态域，需要兼容客户端更新；Linux 预览不是实际 Word 分页，固定版面以 PDF 为准。
