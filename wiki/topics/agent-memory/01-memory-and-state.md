# 01 记忆与状态：究竟保留了什么

核查日期：2026-11-11。[专题导读](README.md) · [来源](sources.md)。

## 1. 同样叫“记住”，变化的对象不同

Anthropic 原文将 agent memory 限定为从经验获得、跨 session 保留、以后作为 context 读取的知识；排除权重更新、单次上下文内学习和为续接窗口做的 compaction。这是原文的局部定义，不要求整个领域都采用同一词义。[原文定义](sources.md#anthropic)

| 保留对象 | 一个原创例子 | 不应推出什么 |
| --- | --- | --- |
| 当前上下文 | 本次用户刚说过“输出 JSON” | 下次新会话一定知道 |
| Compaction／压缩摘要 | 将本次长轨迹压成待办与结论 | 全部原始细节被保留 |
| 持久笔记／store | 下次仍能读取验证过的配置说明 | 模型参数已经更新 |
| 工具环境状态 | 文件、数据库事务、运行中的服务 | 这些状态等同知识记忆 |
| 模型参数 | 训练改变网络的权重 | 某条可删除笔记对应一个参数 |
| KV cache | 重用一次推理中的计算状态 | 能替代跨会话、可审计的事实库 |

表格是教学分解。持久记忆在下次被读入时，仍通过当前上下文影响推理；“记忆与单次 ICL 的定义不同”不意味着使用记忆时完全没有 in-context learning。[机制与产品边界](sources.md#architecture)

## 2. 将“经验”拆成观察、推断与规则

原创调试场景：

1. 工具观察：程序报告输出单位为 kJ。
2. Agent 推断：可能不需要再次转换单位。
3. 核验：查当前版本接口并通过一个已知值测试。
4. 可保存规则：在版本 v2 中，该接口直接输出 kJ；若版本变更，需重查。

四项的证据强度不同。将猜测直接写成“已经验证”，会让后续会话失去原来的不确定性。保存一次成功答案，也不等于得到可推广的规则；还要保存它在什么条件下成功。

建议的最小事实记录是：

```text
claim · original_source · source_version · observed_at
scope · verification_state · validity_condition · supersedes
```

这是本 Wiki 的记录建议。它区分事实来源与修改记录：谁编辑了文件、文件 hash 是什么，都不能单独证明 claim 为真。官方 wiki 示例同样要求保留来源、日期和不确定性，见[来源与修改 provenance](sources.md#provenance)。

## 3. 不是所有历史都值得进入记忆

若某条状态每次都能直接读到，复制它可能比重新读取更危险：旧库存、旧进程状态、旧账户余额都有很短的有效期。

原创选择问题可以写成：

$$
U(m,Q)=V_{\rm reuse}(m,Q)-C_{\rm read}(m,Q)-R_{\rm stale}(m,Q).
$$

这是定性的价值账本，不是一个已经训练的打分器。它提醒我们把未来复用价值、检索开销和过期风险一起考虑；公式中的量需要具体定义，不能仅靠模型自报的 confidence 填上数字。

倾向保存难以恢复的决策理由、经过验证的操作规则和明确偏好，但不是一条无条件规定。某些事故调查需要完整事件；某些长期任务需要细粒度状态。原文也显示，固定写入规则的效果依赖模型和任务，不能把“只记失败”当作普遍最佳策略。[原文实验边界](sources.md#evaluation)

## 4. 文件在，并不代表它会被用到

分析路径可以拆为：

```text
历史是否留下 → 当前是否找到 → 是否适用 → 是否采纳 → 是否正确执行
```

原创反例：一条历史偏好“通常导出 CSV”被准确召回，但当前用户明确要求 JSON。检索器没有错；助手若仍输出 CSV，问题发生在适用与采纳阶段。

因此应分别测试存储、召回、适用性、指令优先级和执行收益。已有[OpenMOSS 记忆评测](../deep-learning/openmoss/06-agent-memory-and-executable-evaluation.md)提供更细的研究协议分析；高语义 recall 不能直接替代产物质量。

## 5. 自主记忆不代表自主训练

Agent 可以改变笔记、索引和工作策略，而基础模型权重保持不变。这种系统级适应可以很有价值，但要避免把它宣传成“模型已学会训练自己”。反过来，若确实更新权重，又需要另一套数据授权、遗忘和模型回滚合同。

“Dreaming 在空闲时间运行”描述的是调度方式，不规定一定有梯度更新。Sleep-time Compute 的一条路线是在后续问题出现前重表示已知 context。[Sleep-time Compute 原论文](https://arxiv.org/html/2504.13171v1)；与[自我改进的对象分层](../deep-learning/self-improvement/concepts-and-foundations.md)对读。

## 自测

1. 一条笔记跨会话保留，权重就更新了吗？**没有，首先确认改变的是哪个对象。**
2. 来源可追溯，事实就一定对吗？**不是，原始观察本身也可能错误。**
3. 精确召回 CSV 偏好，能否覆盖本次 JSON 要求？**不能，相关性不是权限或当前适用性。**
