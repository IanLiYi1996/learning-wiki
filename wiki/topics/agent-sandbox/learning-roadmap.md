# 学习路线与问题卡：从看懂隔离到写出可验收方案

整理日期：2026-11-04。本路线是 Wiki 自定义的学习顺序，不是厂商课程、认证或采购评分体系。

## 路线一：第一次接触

01 → 02 → 04 → 08 → 09。先画组件与威胁，再理解容器共享 kernel、VM guest 和外部权限。学习完成的标志不是记住厂商名，而是能解释“执行不逃逸为什么仍可能删除业务数据”。

建议产出一张任务卡：谁提供代码、处理什么数据、需要哪些工具、身份代表谁、结果如何交付。用[术语表](glossary.md)查 KVM／VMM／guest，避免一开始把它们当同义词。

## 路线二：平台工程

02 → 03 → 04 → 06 → 09 → 10。已有 Kubernetes 的团队重点看 RuntimeClass、Pod 粒度、controller、CNI、存储与 broker 分工。没有集群维护经验时，先评估托管服务责任，而不是仅比较运行时二进制大小。

建议产出 ADR、允许／拒绝合同、版本账本、创建／取消／恢复／销毁状态图和可复现 benchmark 计划。PoC 是下一项另行授权工作，不包含在本专题的本地教学测试里。

## 路线三：产品与云方案讨论

01 → 07 → 08 → 09 → 10。重点阅读平台章的 class／compute type／snapshot type／版本／preview 标签，检查服务是否满足业务约束，而非用启动数字决定采购。

建议带着以下问题与供应商讨论：

- 哪个具体运行类型承担不可信代码边界？
- 网络、文件、设备、runtime 和身份能否由 guest 放宽？
- 什么状态保存到暂停、快照和备份，保存多久？
- tenant／user／session 映射由谁负责？
- 未经允许的输出、日志、artifact 和模型调用由谁阻断？
- 哪些能力是 GA、Beta、Alpha、Preview 或版本特定？
- 账户、地域、支持矩阵、合同与独立证据能补齐哪些未知？

## 路线四：小工具与隐私模型

05 → 09 → 08。先看能否把能力收窄成 Wasm host API；再问是否真的不信任宿主。两种目标不同：工具接口窄化不等于硬件保护内存，TEE 测量也不等于工具动作获准。

建议产出 imports 列表与 host function 授权表，或者证明与密钥发布政策。不是先选一个最复杂技术再倒推需求。

## 15 张口头自测卡

| 问题 | 能合格回答的关键点 |
| --- | --- |
| Sandbox 与 microVM 什么关系？ | 约束目标／执行环境，与一种实现路径不同层 |
| OCI image 能证明共享 kernel 吗？ | 不能；要看运行时 |
| cgroups 与 seccomp 是否完整 sandbox？ | 分别约束资源与系统调用，需要其他机制 |
| non-root、rootless、userns-remap 什么不同？ | 工作负载、daemon 和 UID 映射分别分析 |
| gVisor KVM 与 Firecracker 一样吗？ | 应用内核／进程模型与普通 guest VM 路径不同 |
| Kata 的 Pod 中有两个 container，是两台 VM 吗？ | 不应默认；通常 Pod 是 VM sandbox 单元 |
| Firecracker 自动过滤所有网络吗？ | 不替平台完成出站政策 |
| 有快照意味着可重复任意恢复吗？ | 唯一性、凭证、连接、硬件和版本要处理 |
| 恢复内存为何不保证副作用 exactly-once？ | 外部系统已提交与 guest 状态可能不一致 |
| Sandbox CRD 负责内核隔离吗？ | 编排器委托实际 runtime |
| Wasm 有没有自动 host API 安全？ | imports 与宿主实现决定能力范围 |
| TEE 保护宿主，还是减少对宿主信任？ | 必须看信任方向、测量和具体模型 |
| 允许域名是否允许所有 API 操作？ | 可达性与业务授权不同 |
| 暂停／终止是否表示所有数据已删除？ | compute、snapshot、artifact、log／backup 分开 |
| 20 ms 的数字能否决定平台更优？ | 计时口径、配置、成功率、成本分母要相同 |

## 一个不联网的学习作业

先做[三个离线实验](lab.md)，再给假想“用户上传仓库并编译测试”的平台写一页方案。必须包含不可信主体、隔离粒度、候选机制、硬门槛、允许网络与身份、状态清理、失败路径、性能口径和未测试项。

若你的方案只包含“用了某 microVM 品牌，所以安全”，还没有完成。若能说出为什么某个候选被硬约束拒绝，以及其余候选需要哪些测试，就已把资料转为可执行的研究计划。
